# BRD — ขายบอท LINE OA "ป้าเข็ม" (White-Label Bot-as-a-Product)

- สถานะ: ร่าง v0.1 — รอเจ้าของยืนยัน 3 จุด (ดูหัวข้อ 10)
- วันที่: 16 ส.ค. 2026
- ผู้จัดทำ: วิศวกรผู้ช่วย (AI) — ไม่ใช่ผู้มีอำนาจตัดสินใจทางธุรกิจ
- สถาปัตยกรรมที่แนะนำ: **แบบ A (Hosted Silo / Instance-Per-Tenant)** ระยะแรก

---

## 1. บทสรุปผู้บริหาร (Executive Summary)

บอท "ป้าเข็ม ขายของ" คือ **LINE Official Account ที่ขายสินค้า** — ลูกค้าแอดไลน์แล้วพิมพ์
"อยากได้หูฟังงบ 500" บอทจะค้นหาสินค้าจากคลัง (เฉพาะลิงก์ affiliate ที่ตรวจผ่านแล้ว)
แนะนำ + แนบลิงก์สั่งซื้อ พร้อมระบบจำความชอบ / แจ้งราคาตก / แนะนำของใหม่

เป้าหมาย: **นำบอทตัวนี้ไปขายต่อ** ให้ร้านค้า/ผู้ประกอบการรายอื่น โดยแต่ละรายได้บอท
LINE OA ของตัวเองที่เปลี่ยน **ชื่อบอท / บุคลิก / สินค้า / ลิงก์ / โทเคน LINE** ได้
โดยไม่ต้องเขียนโค้ด (White-Label)

กลยุทธ์: เริ่มจาก **แบบ A** เพื่อออกตลาดเร็ว (1–2 สัปดาห์) แล้วจึงประเมินการยกระดับ
เป็น **แบบ C (SaaS Multi-Tenant)** เมื่อมีลูกค้าจ่ายเงินจริง ≥ 10–20 ราย

---

## 2. เป้าหมายทางธุรกิจ (Business Objectives)

1. สร้างรายได้จากโค้ดที่มีอยู่แล้ว โดยไม่ต้องเขียนบอทใหม่ต่อราย
2. ให้ลูกค้าแต่ละรายได้บอท LINE OA ขายสินค้าของตัวเองโดยเร็ว (onboarding < 1 วัน)
3. ลดภาระการตั้งค่า — ของที่ซ้ำกัน (บุคลิก / การค้นหา / แจ้งเตือน / แดชบอร์ด) ใช้ร่วมกัน
   ของที่ต่างกัน (ชื่อร้าน / สินค้า / ลิงก์) แยกต่อราย

## 3. ลูกค้าเป้าหมาย 🔴 รอเจ้าของยืนยัน

| ตัวเลือก | รายละเอียด |
|---|---|
| ก. ร้านค้ารายย่อย (มี LINE OA อยู่แล้ว) | ขายสินค้าตัวเอง อยากได้บอทช่วยตอบ/แนะนำ |
| ข. คนทำ Shopee Affiliate (เหมือนเจ้าของเดิม) | ขายของจากคลัง affiliate |
| ค. ทั้งคู่ | เปิดกว้างที่สุด แต่ต้องออกแบบคลังสินค้าให้ยืดหยุ่น |

## 4. ขอบเขต (In / Out of Scope)

**In scope (Phase 1 + 2):**
- Bot Profile: ชื่อบอท, บุคลิก/เสียง, ลิงก์ LINE OA, โทเคน LINE, คลังสินค้า, ลิงก์ affiliate
- หน้าแอดมินตั้งค่า profile (แทนการแก้โค้ด)
- แยกข้อมูลร้าน (products / chat_logs / preferences) ต่อราย

**Out of scope (Phase 1):**
- ระบบชำระเงิน / แพ็กเกจ / ใบเสร็จ
- ระบบสมัครสมาชิกแบบ self-service (ลูกค้าลงทะเบียนเอง)
- Multi-tenant shared DB (แบบ C) — เก็บเป็น roadmap ระยะถัดไป

## 5. ผลิตภัณฑ์ (สิ่งที่ขาย)

บอท LINE OA ขายสินค้า ประกอบด้วยฟีเจอร์ปัจจุบัน:

1. 🔍 ค้นหาสินค้าจากคลัง (link_status = ok เท่านั้น) + กรองงบ/ราคา
2. 🧠 จำความชอบลูกค้า (Account Memory) + แนะนำของตรงใจ
3. 📉 แจ้งราคาตก / 🔥 ของใหม่สำหรับลูกค้าเงียบ (re-engage)
4. ⚖️ เทียบสินค้า / จัดอันดับขายดี
5. 📊 แดชบอร์ดแอดมิน (สถิติ / จัดการสินค้า)
6. 📝 บันทึกแชทลง Google Sheets + PDPA (ลบข้อมูลฉัน)
7. (ตัวเสริม) Facebook auto-post + Social Demand Radar

**ส่วนที่ต้อง White-Label ต่อราย:** ชื่อบอท, บุคลิก/เสียง, ลิงก์ LINE OA,
โทเคน LINE, คลังสินค้า + ลิงก์ affiliate, (ตัวเลือก) เพจ Facebook

## 6. ข้อกำหนดการทำงาน (Functional Requirements)

### Phase 1 — Bot Profile / White-Label (รากฐานร่วมของ A และ C)
- FR-1: ระบบเก็บ "โปรไฟล์ร้าน" ในฐานข้อมูล (ชื่อ, persona, line_oa_url, line_token, admin_user_id)
- FR-2: โค้ดทั้งหมดอ่านชื่อบอท/บุคลิกจากโปรไฟล์ แทนการฝัง "ป้าเข็ม" แข็ง ๆ (~15 ไฟล์)
- FR-3: หน้าแอดมิน `/admin` เพิ่มแท็บตั้งค่าโปรไฟล์ (แก้ + บันทึกโดยไม่ deploy)
- FR-4: คลังสินค้า + ลิงก์ affiliate แยกต่อโปรไฟล์ (ไม่ปนกัน)

### Phase 2 — โหมดขาย (แบบ A)
- FR-5: สร้าง "ร้านใหม่" = ก็อปโปรไฟล์ + คลังเปล่า + โทเคน LINE ของร้านนั้น (1 instance ต่อร้าน)
- FR-6: แดชบอร์ดแอดมินของแต่ละร้านเห็นเฉพาะข้อมูลร้านตัวเอง

## 7. มาตรฐานประสบการณ์ลูกค้า (Customer Experience Standards)

มาตรฐานการบริการ 5 ขั้นตอน (จากอินโฟกราฟิก "5 ขั้นตอนสู่ประสบการณ์ลูกค้าที่ยอดเยี่ยม") —
ใช้เป็นแนวทางให้บอทปฏิบัติต่อลูกค้าทุกราย และเป็นจุดขาย (selling point) ให้ผู้ซื้อบอท:

| ขั้น | ชื่อ | พฤติกรรมที่คาดหวังจากบอท |
|---|---|---|
| 1 | การต้อนรับที่อบอุ่น | ทักทายอย่างอบอุ่น, เป็นกันเองและสุภาพ, พร้อมให้บริการเสมอ (24 ชม.) |
| 2 | การรับฟังอย่างตั้งใจ | เข้าใจความต้องการ (วิเคราะห์เจตนา/งบประมาณ), ไม่ขัดจังหวะ, ยืนยันข้อมูลเพื่อความถูกต้อง |
| 3 | การนำเสนอทางเลือกที่เหมาะสม | แนะนำสินค้าที่ตรงจุด (จากคลัง link ok), ให้ข้อมูลชัดเจนครบถ้วน (ราคา/จุดเด่น/จุดอ่อน), ตอบข้อสงสัยอย่างจริงใจ |
| 4 | การดำเนินการที่รวดเร็วและมีประสิทธิภาพ | ลดขั้นตอนยุ่งยาก, แจ้งสถานะการทำงาน, แก้ไขปัญหาทันที |
| 5 | การติดตามผลและขอบคุณ | สอบถามความพึงพอใจ, รับฟังความคิดเห็น, กล่าวคำขอบคุณอย่างจริงใจ |

**ข้อกำหนดเพิ่มเติม:**
- FR-7: บอทตอบสนองตามมาตรฐาน 5 ขั้นตอนนี้ในทุกบทสนทนา
- FR-8: (ทางเลือก) มีคอนเทนต์ "มาตรฐานการบริการ" ให้ลูกค้าดูได้ (เช่น เมนู / โพสต์แนะนำตัว)
- FR-9: สโลแกน "ความพึงพอใจของคุณคือความสำเร็จของเรา" ใช้เป็น tagline ในข้อความ/คอนเทนต์ของบอท (เปลี่ยนได้ต่อร้าน)

## 8. ข้อกำหนดที่ไม่ใช่การทำงาน (Non-Functional)

- **NFR-1 การแยกข้อมูล (Isolation):** ข้อมูลร้านหนึ่งต้องไม่รั่วไปอีกร้าน (แบบ A แยก DB/instance)
- **NFR-2 PDPA:** ลบข้อมูลลูกค้าได้เมื่อสั่ง "ลบข้อมูลฉัน" (สืบทอดจากระบบเดิม)
- **NFR-3 ความปลอดภัย:** โทเคน LINE / คุกกี้ ต้องไม่ถูก commit เข้า Git (มี `.gitignore` อยู่แล้ว)
- **NFR-4 เสถียรภาพ:** รักษากลไก pool_pre_ping / keep-alive / failover LLM เดิมไว้
- **NFR-5 ต้นทุน:** ใช้ free tier (Render + Supabase) ได้นานที่สุด ก่อนยกระดับ

## 9. โมเดลธุรกิจและราคา 🔴 รอเจ้าของยืนยัน

| ตัวเลือก | ข้อดี | ข้อเสีย |
|---|---|---|
| ขายขาดครั้งเดียว | ได้เงินเร็ว | ไม่มีรายได้ประจำ, ไม่คุ้มค่าดูแลระยะยาว |
| รายเดือน (subscription) | รายได้ประจำ (Annuity) | ต้องมีระบบเก็บเงิน/เตือน |
| แพ็กเกจ (เริ่มต้น/มือโปร) | เก็บส่วนต่างตามฟีเจอร์ | ออกแบบแพ็กเกจเพิ่ม |

**ยังไม่สรุป:** ราคาต่อร้าน / ความถี่เก็บเงิน / ใครออกค่า LINE OA และเซิร์ฟเวอร์

## 10. สมมติฐานและข้อพึ่งพา (Assumptions & Dependencies)

- ลูกค้าแต่ละรายมี LINE OA ของตัวเอง (หรือใช้ที่แอดมินจัดหาให้)
- ใช้ Supabase / Render ของแอดมินเป็นโครงสร้างหลัก (แบบ A = instance แยกบนโครงสร้างเดิม)
- ฟีเจอร์ Facebook auto-post เป็นตัวเลือก — บอทหลักที่ขายคือ LINE OA (ไม่บังคับ FB)

## 11. การตัดสินใจที่รอเจ้าของ (Open Decisions)

1. 🔴 **ลูกค้าเป้าหมาย** — ร้านค้ารายย่อย / คนทำ affiliate / ทั้งคู่?
2. 🔴 **ราคาขาย** — ขายขาด / รายเดือน / แพ็กเกจ? ราคาเท่าไร?
3. 🔴 **ใครตั้งค่าบอท** — แอดมินตั้งให้ทีละร้าน / ลูกค้าตั้งเองผ่านหน้าเว็บ?

> เมื่อเจ้าของตอบ 3 ข้อนี้ครบ จะล็อก BRD เป็น v1.0 แล้วไปทำ SRS → System & DB Design
> ตามลำดับ SDLC โดยยังไม่เขียนโค้ดจนกว่าข้อตกลง (BRD/SRS) จะได้รับการยืนยัน
