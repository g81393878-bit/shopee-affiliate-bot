# 📋 รายงานสรุปการวิเคราะห์ปัญหาและการแก้ไขตรงจุด (Root Cause Analysis - RCA)
**วันที่บันทึก:** 30 สิงหาคม 2026  
**ระบบ:** Shopee Affiliate Automation & LINE OA PaKhem Bot Ecosystem

## 🎯 วัตถุประสงค์ของเอกสารนี้
บันทึกประวัติข้อผิดพลาดที่เกิดขึ้นจริงในระบบ, การแก้ไขช่วงแรกที่ไม่ตรงจุดและเหตุผล, สาเหตุที่แท้จริง (Root Cause), และวิธีการแก้ไขที่ถูกต้องแม่นยำ 100% เพื่อเป็นมาตรฐานและคู่มือป้องกันความผิดพลาดสำหรับนักพัฒนาและเอเจนต์ AI ทุกตัวในอนาคต

## 1. ปัญหา: ลูกค้าทัก LINE มาแล้วบอทเงียบสนิท ไม่ตอบรับใดๆ

### ❌ สิ่งที่แก้ไขช่วงแรกแต่ไม่ตรงจุด:
* พยายามแก้ไขโค้ดการประมวลผลคำสั่ง, โค้ดคำทักทาย, หรือระบบ AI Round-Robin
* **เหตุผลที่ไม่ตรงจุด:** ปัญหาไม่ได้อยู่ที่โค้ดประมวลผลคำสั่ง แต่ข้อความจาก LINE **ไม่เคยวิ่งมาถึงเซิร์ฟเวอร์เลยแม้แต่ไบต์เดียว**

### 🔍 สาเหตุที่แท้จริง (Root Cause):
* Cloudflare Quick Tunnel (`trycloudflare.com`) ทุกครั้งที่เน็ตกระตุกหรือโปรเซสรีสตาร์ท มันจะสุ่ม Subdomain URL ใหม่ (เช่น จาก `shorts-realm...` เป็น `tale-favorite...`) แต่ LINE Webhook Console ยังคงชี้ไปที่ URL เก่า ทำให้ LINE ส่งข้อมูลมาแล้วเจอ 404 / Connection Timeout

### 🟢 การแก้ไขที่ตรงจุด 100%:
* พัฒนาและติดตั้งบริการ **`tools/tunnel_watchdog.py`** รันเป็น OS Systemd Service (`tunnel-watchdog.service`) แยกอิสระ
* ทำหน้าที่อ่าน URL จริงของ Cloudflare และตรวจสอบทุกๆ 15 วินาที
* หาก URL เปลี่ยน จะยิงคำสั่งไปอัปเดต LINE Webhook Endpoint ผ่าน LINE API (`PUT https://api.line.me/v2/bot/channel/webhook/endpoint`) อัตโนมัติทันที

## 2. ปัญหา: บอทตอบรับ แต่บอกว่า "ไม่พบสินค้า / หาสินค้าไม่เจอ" (เช่น เสื้อ, ถุงเท้า, รองเท้า)

### ❌ สิ่งที่แก้ไขช่วงแรกแต่ไม่ตรงจุด:
* พยายามปรับแต่งฟังก์ชันตัดคำไทย (PyThaiNLP Tokenizer), ปรับพจนานุกรมหมวดหมู่ (Category Keywords), และลดเกณฑ์ยอดขาย `MIN_SALES >= 2000`
* **เหตุผลที่ไม่ตรงจุด:** ต่อให้ฟังก์ชันค้นหาฉลาดแค่ไหน **ถ้าไปค้นในตารางฐานข้อมูลที่มีสินค้า 0 ชิ้น ผลลัพธ์ก็คือ 0 ชิ้นเสมอ**

### 🔍 สาเหตุที่แท้จริง (Root Cause):
* ในไฟล์ `backend/.env` บนเซิร์ฟเวอร์ VPS ค่า `DATABASE_URL` ถูกตั้งเป็น `sqlite:///./affiliate_db.db` ซึ่งเป็นไฟล์ฐานข้อมูล SQLite สำรองที่ว่างเปล่า (มีสินค้า 0 รายการ) ในขณะที่สินค้าจริงทั้ง **2,472 รายการ** อยู่ใน **Supabase PostgreSQL**

### 🟢 การแก้ไขที่ตรงจุด 100%:
* แก้ไข `DATABASE_URL` ใน `backend/.env` ทั้งหมดให้ชี้ตรงไปยัง **Supabase PostgreSQL Transaction Pooler** (`aws-0-ap-southeast-1.pooler.supabase.com:6543/postgres`)
* เมื่อค้นหาคำว่า "เสื้อ", "ถุงเท้า", "หูฟัง", "กระติกน้ำ", "รองเท้า" ระบบจึงดึงสินค้าจริงจากคลัง 2,472 รายการ และส่งการ์ด Flex Message ให้ลูกค้าได้ทันที 100%

## 3. ปัญหา: ลูกค้าดูคลิป YouTube/Reels แล้วพิมพ์เลขรหัสสินค้า (เช่น "86", "447") แต่บอทไม่ส่งการ์ดสินค้า

### ❌ สิ่งที่แก้ไขช่วงแรกแต่ไม่ตรงจุด:
* คิดว่าสินค้าชิ้นนั้นหมด หรือฟังก์ชันค้นหาชื่อสินค้าไม่เจอ
* **เหตุผลที่ไม่ตรงจุด:** ในคลิปวิดีโอ แปะป้ายบอกคนดูว่า *"แอด LINE @137gsref พิมพ์ 86"* แต่โค้ด `parse_product_code` ในระบบเดิมถูกเขียนให้ดักจับเฉพาะข้อความที่มีคำนำหน้า เช่น `"รหัส 86"` หรือ `"code 86"` เท่านั้น เมื่อลูกค้าพิมพ์ตัวเลขโดดๆ เช่น `86` หรือ `86 ครับ` ระบบจึงคิดว่าเป็นคำค้นหาข้อความทั่วไป

### 🔍 สาเหตุที่แท้จริง (Root Cause):
* ฟังก์ชัน `parse_product_code` ขาด Regex ที่รองรับตัวเลขล้วน (Pure Digits) และตัวเลขผสมคำลงท้ายสุภาพ

### 🟢 การแก้ไขที่ตรงจุด 100%:
* ปรับปรุงฟังก์ชัน `parse_product_code` ใน `backend/app/api/line_bot.py`:
  1. ตัดคำสุภาพก่อน (`_strip_polite_suffix`)
  2. รองรับตัวเลขล้วน 1-5 หลัก (`86`, `447`, `1628`)
  3. รองรับคำนำหน้าภาษาไทยและสากล (`เลข 86`, `เบอร์ 86`, `ชิ้นที่ 86`, `#86`, `p86`)
* ส่งผลให้เมื่อลูกค้าพิมพ์ตัวเลข ระบบจะเข้าสู่ `handle_direct_product_code` และยิงการ์ดสินค้าตรงตัวพร้อมลิงก์ Shopee Affiliate ให้ทันทีใน **0.1 วินาที**

## 4. ปัญหา: Telegram แจ้งเตือนรัว และระบบผลิตคลิปวนซ้ำค้าง

### ❌ สิ่งที่แก้ไขช่วงแรกแต่ไม่ตรงจุด:
* สั่งรีสตาร์ทบริการใหม่ซ้ำๆ ซึ่งยิ่งทำให้ระบบยิงข้อความเริ่มระบบใหม่ซ้ำๆ เข้าไปอีก

### 🔍 สาเหตุที่แท้จริง (Root Cause):
1. **Startup Alert Storm:** มีโค้ดยิงแจ้งเตือนสถานะตอนเปิดเครื่องใน `system_runner.py` ซ้ำซ้อนกัน 3 ตัวในเสี้ยววินาที
2. **Empty DB Loop:** ตัวผลิตคลิปอัตโนมัติมองเห็นสินค้าใน SQLite เป็น 0 ชิ้น จึงวนลูปพยายามค้นหาสินค้าใหม่ทุกๆ 1 นาที

### 🟢 การแก้ไขที่ตรงจุด 100%:
1. ตัดโค้ดแจ้งเตือนเริ่มต้นระบบซ้ำซ้อนใน `system_runner.py` ออกทั้งหมด
2. เชื่อมต่อฐานข้อมูล Supabase สำเร็จ ทำให้ตัวผลิตคลิปมองเห็นสินค้า 2,472 ชิ้น จึงผลิตคลิปตามรอบปกติและหยุดวนลูปถาวร

## 6. ปัญหา: ระบบโพสต์ TikTok คลิกปุ่มแล้วคลิปไม่บันทึก หรือชนกันระหว่างบัญชี

### ❌ สิ่งที่แก้ไขช่วงแรกแต่ไม่ตรงจุด:
* พยายามคลิกปุ่ม Post ซ้ำๆ หรือเปลี่ยน selector ปุ่มแบบลอยๆ โดยไม่ดูสถานะ Overlay
* **เหตุผลที่ไม่ตรงจุด:** ปัญหาเกิดจาก 3 ชั้นซ้อนกัน: (1) เมนูแนะนำแฮชแท็ก Dropdown ลอยมาบังปุ่ม, (2) มี Modal ป๊อปอัปถามยืนยัน "Continue to post? -> Post now" ซ่อนอยู่, และ (3) โฟลเดอร์ User Data เดิมเขียนทับเซสชันระหว่างบัญชี

### 🔍 สาเหตุที่แท้จริง (Root Cause):
1. **Dropdown & Modal Overlays:** เมื่อพิมพ์ `#` ในแคปชั่น TikTok จะเปิด dropdown ที่ดักจับ pointer events ทำให้คลิกปุ่มไม่ถึงตัวจริง และเมื่อกด Post จะมี Modal ยืนยันรอบสอง (`Post now`)
2. **Session Pollution:** การใช้ `launch_persistent_context` แชร์โฟลเดอร์เดียวกันทำให้บัญชีที่ 2 สลับไปใช้ข้อมูลบัญชีที่ 1

### 🟢 การแก้ไขที่ตรงจุด 100%:
1. **Stateless Isolation:** เปลี่ยนมาใช้ `browser.new_context()` และฉีด Cookie JSON แยกตามไฟล์บัญชีเด็ดขาด 100%
2. **Escape Key Dismissal:** ส่งคีย์ `Escape` ทันทีหลังพิมพ์แคปชั่นเสร็จ เพื่อปิดหน้าต่าง Dropdown แฮชแท็ก
3. **Double Confirmation Handler:** เพิ่มลูปตรวจจับและคลิกปุ่มยืนยัน `Post now` / `โพสต์เลย` หลังการกดโพสต์รอบแรก
4. **Account Warm-up:** บัญชีเปิดใหม่ต้องโพสต์คลิปแรกผ่านแอปมือถือ 1 ครั้ง เพื่อปลดล็อค Anti-Bot Web Studio

## 7. กฎเหล็กและข้อควรระวังสำหรับระบบในอนาคต (Engineering Guidelines)
1. **ห้ามเปลี่ยน `DATABASE_URL` เป็น SQLite ใน Production เด็ดขาด:** ต้องเป็น Supabase PostgreSQL เสมอ
2. **รหัสสินค้าจากคลิปต้องดักจับทั้งตัวเลขล้วนและตัวเลขผสมคำสุภาพเสมอ**
3. **การแจ้งเตือนงานหลังบ้านทั้งหมดต้องเข้า Telegram Commander เท่านั้น:** ห้ามใช้ LINE OA Push Message เพื่องานหลังบ้าน เพื่อสงวนโควต้าฟรี 300 ข้อความ/เดือนไว้คุยกับลูกค้า 100%
4. **`tunnel-watchdog.service` ต้องรันคู่ขนานกับ `cloudflared-tunnel.service` ตลอด 24 ชม. เสมอ**
5. **ระบบ TikTok Automation ต้องใช้ Stateless Context และมีตัวดักจับปุ่ม `Post now` เสมอ**
