## 1. บทนำและที่มาของเหตุการณ์

ในกระบวนการพัฒนาระบบผลิตคอนเทนต์ไวรัลอัตโนมัติ 24 ชั่วโมงของระบบ "บอทป้าเข็ม" ทีมงานได้พัฒนาโมดูลผลิตคลิปวิดีโอแบบสแตนด์อโลน (`reels_uploader/standalone_content_generator.py`) โดยตั้งเป้าหมายไว้ในทางทฤษฎีว่า:
- มี **"ฮุก 3 วินาทีหยุดนิ้วคนดู"**
- ออกแบบเพื่อคน **85% ที่ปิดเสียงดูคลิป (Mute-First Visual)**
- สรุป 3 สาระสำคัญผ่านกล่องการ์ด

อย่างไรก็ตาม เมื่อนำระบบไปเรนเดอร์คลิปวิดีโอจริงตัวแรก (`content_celebrity_trend_1788662602.mp4`) ผู้ใช้งานได้ทำการสกรีนช็อตภาพวิดีโอจริงบนหน้าจอมือถือขึ้นมาแสดง พร้อมให้ฟีดแบ็กที่ชัดเจนและตรงไปตรงมาว่า:
> **"คุณคิด ดีมาก สวยงาม แต่ ทำไม่ได้"**

และเมื่อทีมงานพยายามสร้างสคริปต์ทดสอบกระจัดกระจาย ผู้ใช้งานได้ตักเตือนเพิ่มเติมว่า:
> **"คู่มือก็ทำมาเยอะแยะ แต่ไม่อ่านอะไรเลย แล้วจะทำให้เปลืองโทเคนทำไม มีแค่น้อยๆ ก็พอ เขียนลง Master Google Docs เลย ไม่รกโค้ดด้วย"**
> **"เขียนเป็นเคสศึกษา การทำวิดีโอ ว่าทำอะไรผิด แก้ไขอย่างไร เพื่อจะได้ไม่ทำผิดอีก เพื่อพัฒนาต่อยอดได้เรื่อยๆ"**

เอกสารฉบับนี้จึงถูกจัดทำขึ้นเป็น **กรณีศึกษาเชิงลึก (Master Case Study)** เพื่อบันทึกความผิดพลาด สาเหตุที่แท้จริง วิธีการแก้ไขเชิงโค้ด และกฎเหล็กเพื่อป้องกันไม่ให้เกิดความผิดพลาดซ้ำในอนาคต

## 2. การวิเคราะห์สาเหตุเชิงลึก (Root Cause Analysis - RCA)

### 2.1 ปัญหาเลย์เอาต์ Infographic กินพื้นที่ 70% (The PowerPoint Slide Dilemma)
* **พฤติกรรมเดิม:** โค้ดนำกล่องสีขาว Infographic ขนาดใหญ่ (`W - 100`, สูงเกือบ 800px) พร้อมกล่องย่อย 3 ขั้นตอน (`Step 1, Step 2, Step 3`) มาวางทับบนรูปภาพตรงกลางจอ
* **ผลกระทบ:** รูปภาพเหตุการณ์/คนดังจริงถูกบีบเหลือเป็นเพียงหน้าต่างเล็กๆ ด้านบน (860x600px) ในขณะที่พื้นที่ 70% ของหน้าจอกลายเป็นแผ่นกระดาษข้อความสีทึบ
* **สาเหตุที่แท้จริง:** ผู้พัฒนาสับสนระหว่าง **"การ์ดสินค้า E-Commerce Shopee"** (ซึ่งต้องการพื้นที่แสดงสเปก, เรตติ้ง, ราคา) กับ **"คลิปวิดีโอสั้นไวรัล (TikTok/Reels/Shorts)"** (ซึ่งคนดูต้องการเสพภาพ Visual เต็มตาใน 0.5-1 วินาทีแรก) การใส่กล่องข้อความทึบทำให้คลิปดูเหมือน "สไลด์ PowerPoint บรรยายสรุป" หรือ "แบบฟอร์มรายงาน" คนเล่นโซเชียลจะปัดฟีดผ่านทันที

### 2.2 ปัญหาตัวอักษรเต้าหู้ [ ] จาก Unicode Emojis (Missing Glyph Trap)
* **พฤติกรรมเดิม:** ในกล่องสรุปข้อความ โค้ดพยายามใส่ Unicode Emojis เช่น `✨ 1.`, `🔥 2.`, `💡 3.`, `🔇` เพื่อเพิ่มสีสัน
* **ผลกระทบ:** บนระบบปฏิบัติการ Windows ฟอนต์ภาษาไทย TrueType มาตรฐาน (`leelawdb.ttf`, `tahomabd.ttf`, `leelawadeeui.ttf`) ไม่มี Glyph สำหรับ Emoji สีเหล่านี้ ทำให้ Pillow วาดผลลัพธ์เป็น **กล่องสี่เหลี่ยมเต้าหู้ `[] 1. สังเกต...`** ส่งผลให้คลิปดูไม่เป็นมืออาชีพและเหมือนระบบบั๊ก
* **สาเหตุที่แท้จริง:** ความพยายามพึ่งพา Emoji ในการจัดเลย์เอาต์ โดยไม่ได้ทดสอบ Mask Size และความเข้ากันได้ของ TrueType Engine กับ Unicode Supplementary Planes

### 2.3 ปัญหาการตัดคำภาษาไทยผิดจังหวะธรรมชาติ (Unnatural Word Wrap)
* **พฤติกรรมเดิม:** ฟังก์ชัน `wrap_thai_lines()` ตัดคำโดยคำนวณจาก `len(cur) + len(t) <= max_chars_per_line` เพียงอย่างเดียว
* **ผลกระทบ:** เมื่อประโยคพาดหัวคือ `"หยุดก่อน! เลขนี้มักวนออกซ้ำ"`:
  - บรรทัด 1: `หยุดก่อน! เลขนี้มัก` (19 ตัวอักษร ซึ่งยังไม่เกิน 20)
  - บรรทัด 2: `วนออกซ้ำ`
  - ผลลัพธ์: คำว่า "มักวนออกซ้ำ" ถูกหั่นครึ่ง คำว่า "มัก" หลุดไปอยู่บรรทัดบน ทำให้ประโยคอ่านแล้วสะดุด ขาดความน่าเชื่อถือ
* **สาเหตุที่แท้จริง:** ไม่มีการตรวจสอบจุดตัดวรรคตอนตามธรรมชาติ (Natural Punctuation Boundary) เช่น เครื่องหมายอัศเจรีย์ `!` หรือปรัศนี `?`

### 2.4 ปัญหาตัวหนังสือเดิมของภาพข่าวแทงทะลุ (Clashing Background Text)
* **พฤติกรรมเดิม:** ภาพถ่ายข่าวจากสำนักข่าวไทย (เช่น Sanook, ไทยรัฐ) มักมีข้อความกราฟิกตัวโตๆ ฝังมาในภาพต้นฉบับ เช่น `นเปิด 3 ตัว` และ `เกิดด่วนออกกอง` เมื่อโค้ดใส่แถบสีดำ Vignette ด้านล่างเริ่มต้นที่ `y=1350` ด้วยค่า Alpha ต่ำ (เริ่มที่ 28)
* **ผลกระทบ:** ข้อความเดิมของสำนักข่าวสว่างจ้าทะลุขึ้นมาชนกับกล่อง Subtitle ของเรา เกิดภาพตัวหนังสือซ้อนทับกันสองชั้น ลายตา และอ่านไม่ออก
* **สาเหตุที่แท้จริง:** การคำนวณความลึกและจุดเริ่มต้นของ Gradient Overlay ด้านล่างไม่ครอบคลุมพื้นที่ที่ภาพข่าวมักวางพาดหัว

### 2.5 ปัญหา Safe Zone ขอบล่างจอสมาร์ตโฟนตัดป้าย Action Bar
* **พฤติกรรมเดิม:** แถบ Conversion Bar ด้านล่างถูกวางไว้ที่ `y=1740 ถึง 1840`
* **ผลกระทบ:** เมื่อผู้ใช้เปิดดูคลิปบนมือถือ หรือแอปเล่นวิดีโอที่มีแถบควบคุมด้านล่าง (Bottom Navigation Bar / SeekBar) แถบ Action Bar จะถูกตัดขาดหรือถูก UI ของโทรศัพท์บดบังมิด

## 3. การปรับปรุงเชิงสถาปัตยกรรมและโค้ด (Engineering Solutions)

เพื่อให้ระบบผลิตวิดีโอมีมาตรฐานระดับสตูดิโอ ไร้บั๊ก และหยุดนิ้วคนดูได้จริง ทีมงานได้ทำการยกเครื่องโค้ดใน `reels_uploader/standalone_content_generator.py` ดังนี้:

### 3.1 สถาปัตยกรรม Cinematic Full-Screen 9:16 (1080x1920 Cover)
ตัดกล่องสีขาว Infographic 3 ชั้นทิ้งทั้งหมด 100% แล้วเปลี่ยนให้ภาพถ่ายจริงครอบคลุมพื้นที่เต็มหน้าจอ:
```python
# 1. Full-Screen Cover 1080x1920: ภาพจริงเต็มจอ 100% ไร้กรอบบดบัง
bg_ratio = max(W / curr_hero_img.width, H / curr_hero_img.height)
scaled_w = int(curr_hero_img.width * bg_ratio)
scaled_h = int(curr_hero_img.height * bg_ratio)
scaled_img = curr_hero_img.resize((scaled_w, scaled_h), Image.Resampling.LANCZOS)
crop_x = max(0, (scaled_w - W) // 2)
crop_y = max(0, (scaled_h - H) // 2)
canvas = scaled_img.crop((crop_x, crop_y, crop_x + W, crop_y + H)).convert("RGBA")
```
* **ผลลัพธ์:** พื้นที่ตรงกลางจอ (ความสูงเกือบ 1,000 พิกเซล) เปิดโล่ง 100% โชว์ภาพเหตุการณ์/คนดัง/สินค้าแบบเต็มตา ทรงพลัง และหยุดนิ้วคนดูได้ทันที

### 3.2 ระบบเว้นวรรคตัดคำอัจฉริยะ (Punctuation-Aware Word Wrap)
ปรับปรุง `wrap_thai_lines()` ให้ตรวจสอบเครื่องหมายวรรคตอนเด่น (`!`, `?`, `•`, `:`) ก่อนเสมอ:
```python
def wrap_thai_lines(text: str, max_chars_per_line: int = 24, max_lines: int = 8) -> List[str]:
    text = clean_render_text(text)
    if not text:
        return []

    # ถ้ามีเครื่องหมายวรรคตอนเด่น เช่น !, ?, •, : ให้ตัดบรรทัดตรงวรรคตอนก่อน เพื่อความสละสลวยเป็นธรรมชาติ
    for punct in ["!", "?", "•", " :", ":"]:
        if punct in text:
            parts = text.split(punct, 1)
            p1 = parts[0].strip() + (punct if punct not in ("•", " :", ":") else "")
            p2 = parts[1].strip()
            if 3 <= len(p1) <= max_chars_per_line and len(p2) >= 3:
                wrapped_p2 = wrap_thai_lines(p2, max_chars_per_line=max_chars_per_line, max_lines=max_lines - 1)
                return [p1] + wrapped_p2
    ...
```
* **ผลลัพธ์:** ข้อความ `"หยุดก่อน! เลขนี้มักวนออกซ้ำ"` จะถูกตัดเป็น:
  - บรรทัด 1: `หยุดก่อน!` (พาดหัวคำโต ดึงดูดสายตา)
  - บรรทัด 2: `เลขนี้มักวนออกซ้ำ` (เนื้อความสมบูรณ์ ไม่ขาดท่อน)

### 3.3 แสงเงา Cinematic Top & Bottom Vignette กลบข้อความเดิม 100%
จากการทดสอบพบว่ารูปข่าว 16:9 มักมีแถบพาดหัวสีแดงสดขนาดใหญ่ (เช่น `...เมียไปหาย...`) คาดอยู่ที่ช่วงล่าง หากใช้สูตร Gradient เดิมที่เริ่มที่ `y=1050` ด้วยความทึบแสงต่ำ จะทำให้แถบสีแดงยังคงแทงทะลุขึ้นมา

**การแก้ไขขั้นเด็ดขาด (Definitive Fix):**
- เริ่มไล่ระดับความมืดตั้งแต่ `y=750` (ใต้ระดับใบหน้าของบุคคล)
- เร่งความทึบแสงจน **ทึบสนิท 100% (alpha=255) ตั้งแต่ `y=1000` ลงไปจนถึงขอบล่าง `y=1920`**:
```python
# 2. Cinematic Gradient Overlays (Top & Bottom Vignette)
overlay = Image.new("RGBA", (W, H), (0, 0, 0, 0))
draw_ov = ImageDraw.Draw(overlay)

# ด้านบน: ค่อยๆ มืดลงเพื่อให้อ่านหัวข้อชัด (0-380px)
for y in range(380):
    alpha = int(210 * (1.0 - (y / 380.0) ** 1.3))
    draw_ov.line([(0, y), (W, y)], fill=(0, 0, 0, alpha))

# ด้านล่าง: ค่อยๆ มืดลงตั้งแต่ y=750 และทึบสนิท 100% ตั้งแต่ y=1000 เพื่อกลบแถบแบนเนอร์/ตัวหนังสือเดิมของรูปข่าว 100%
for y in range(750, H):
    if y < 1000:
        ratio = (y - 750) / 250.0
        alpha = int(255 * (ratio ** 0.8))
    else:
        alpha = 255
    draw_ov.line([(0, y), (W, y)], fill=(10, 15, 26, alpha))

canvas = Image.alpha_composite(canvas, overlay)
```
* **ผลลัพธ์:** แถบแบนเนอร์สีแดงและตัวหนังสือเดิมของสำนักข่าวจะถูกม่านสีเข้มกลบสนิท 100% กลายเป็นผืนผ้าใบมืดระดับโรงภาพยนตร์ที่ส่งให้ Subtitle ลอยเด่นคมชัด ไร้สิ่งรบกวนสายตา

### 3.4 Dynamic Mute-First Subtitles สไตล์ TikTok/CapCut ในแคปซูลทึบคมชัด
เปลี่ยนจากการ์ด 3 ชั้นแช่ค้าง มาเป็นการแสดงผล "แคปซูลซับไตเติลวิ่งทีละประโยค" ใน Lower-Third:

## 5. บทเรียนและแนวทางปฏิบัติเพื่อการพัฒนาต่อยอด (Lessons Learned & Continuous Improvement)

1. **อย่าสับสนระหว่างการทำการ์ดสินค้ากับการทำคลิปสั้น (Video vs Catalog Separation):**
   - การ์ดสินค้า Shopee เน้น "ข้อมูลและสเปก" (รูปอยู่บน กล่องสเปกอยู่ล่าง)
   - คลิปสั้นไวรัล เน้น "อารมณ์และภาพ Visual" (ภาพเต็มจอ 100% + พาดหัวตัวโต + ซับไตเติลวิ่งทีละประโยค)
   - ห้ามนำเทมเพลตการ์ดสินค้ามาครอบคลิปไวรัลเด็ดขาด

2. **อย่าพึ่งพา Unicode Emoji บน Canvas ของ Pillow (Zero Emoji in Pillow):**
   - หากต้องการทำป้ายตัวเลข, ไอคอน หรือกรอบไฮไลท์ ให้วาดด้วย Vector Shapes (`draw.rounded_rectangle`, `draw.circle`) เสมอ ป้องกันการเกิดกล่องเต้าหู้ `[]`

3. **ภาษาไทยต้องเคารพวรรคตอนและความหมาย (Context-Aware Typography):**
   - คำพาดหัวสั้นที่มีเครื่องหมาย `!`, `?` ต้องถูกจัดเป็นบรรทัดนำเดี่ยวๆ เสมอ เพื่อสร้างแรงดึงดูด (Impact) สูงสุด

4. **การประหยัดโทเคนและรักษาความสะอาดของโค้ด (Token Efficiency & Clean Repository):**
   - ห้ามสร้างสคริปต์ทดสอบชั่วคราวกระจัดกระจายในโฟลเดอร์โครงการ
